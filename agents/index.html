The public package is usable through Python. Model Forge, the newer block API, and the optional agent bridge are development previews. Do not infer that an API exists in the installed package from a preview shown here.

Start with a reproducible Python workflow.

  1. Record the installed package version and inspect its actual public API. Use its matching documentation.
  2. State the scientific quantities, observation process, priors, and dimension roles before writing a model.
  3. Build the smallest complete example and check it against known or simulated data.
  4. Select an inference method supported by that interface and model. Retain diagnostics and distinguish point estimates from posterior uncertainty.
  5. Present the assumptions, code, and limitations to the person making the scientific decision.

These are suggested scientific working practices. Repository instructions and the user’s authorization remain the authority for the actual task.

LOCAL DEVELOPMENT PROTOTYPE

An optional bridge for agent-assisted modeling.

The development checkout contains a separately packaged, optional stdio MCP bridge. It exposes a bounded set of model inspection, proposal, review, reporting, and explicitly scoped execution operations over existing CaliPy contracts.

Users supply their own agent host. Starting ordinary CaliPy does not start an AI provider. Model changes and execution have distinct review and permission boundaries.

Availability: the companion bridge is not published to a package registry and this site exposes no remote MCP endpoint. Configuration must come from the supplied development checkout and its current instructions. Do not guess a server URL or an installation command.

Provider-backed end-to-end workflows and broader automation remain development work. A local bridge prototype is not a claim of an autonomous hosted calibration service.
