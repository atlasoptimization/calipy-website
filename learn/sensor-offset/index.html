Guided calibration example

Calibrate a sensor offset,
step by step.

Step 1 / Measurements

Compare the sensor with a known reference.

Suppose a temperature sensor is placed at a stable 20.00 °C reference. Its readings are consistently higher. We want to estimate a constant additive offset, in degrees Celsius.

The data

20.41, 20.52, 20.36, 20.49,
20.44, 20.48, 20.39, 20.51 °C

The average difference from the reference is about +0.45 °C. Individual readings still vary.

Download the readings →
Why does the known reference matter?

Without reference information, a higher sensor reading could reflect a higher true temperature, a positive offset, or both. This lesson treats the reference as exact to isolate the offset question. Real reference uncertainty needs to enter the model.

Next: Model →

Step 2 / Model

Separate reference, offset, and measurement noise.

Our measurement law adds an unknown offset b to the reference r, then allows readings to vary. We assume known, independent Normal measurement noise with standard deviation 0.10 °C.

b ∼ Normal(0, 1) °C
yᵢ ∼ Normal(r + b, 0.10) °C
r = 20.00 °C
Quantity
The shared offset b is a prior-backed unknown. It has one value for this sensor across the readings.
Effect
Addition represents the offset response. The Normal measurement effect describes variation around that response.
Named dimension
The repeat axis identifies the repeated readings; it is not eight separate offset parameters.
Observation
The measured values attach to the stochastic reading output and supply evidence about b.

The prior Normal(0, 1) expresses initial uncertainty about the offset. Its scale is distinct from the 0.10 °C measurement-noise scale.

Step 3 / Python

Express the same model in CaliPy.

This is the model section of the downloadable script. The response equation remains visible, while CaliPy connects the unknown quantity and measurement law.

Python · development API
offset = cp.LatentParameter(
    "offset", prior=dist.Normal(0.0, 1.0)
)
reading = cp.RandomVariable.Normal(
    "reading", scale=0.1
)

@cp.block
def sensor():
    return reading(20.0 + offset())

The script wraps the readings in a CalipyTensor with a named repeat dimension, binds them as observations, and requests posterior inference.

Python · development API
fit = sensor.fit(
    outputs=observations,
    method=cp.NUTS(
        warmup_steps=200, num_samples=500, seed=31
    ),
)
estimate = fit[offset]

Step 4 / Result

Inspect the recorded offset estimate.

The script was executed with real CaliPy inference. These values come from that saved run; clicking through this page does not launch a fit.

+0.448 °CRecorded posterior mean of the offset
0.032 °CRecorded posterior standard deviation

The offset is probably positive under this model. Its posterior uncertainty is smaller than the noise in one reading because the repeated observations inform the same unknown.

An independent analytic calculation gives mean 0.449 °C and standard deviation 0.035 °C. Monte Carlo results need not match those values exactly.

One short teaching chain: 200 warm-up steps and 500 retained NUTS draws, seed 31. The comparison is a small numerical check, not evidence of convergence for arbitrary models.

Step 5 / Interpretation

Use the offset without overstating the calibration.

A correction under this model

Subtract the estimated offset from a reading:

corrected ≈ reading − 0.448 °C

A new reading of 20.90 °C would give a point-corrected value of approximately 20.45 °C. This arithmetic is not a complete uncertainty statement.

What this example does and does not establish

  • The model estimates one constant offset near one reference condition.
  • It does not establish gain, nonlinearity, drift, or transfer across the sensor’s operating range.
  • New measurements still have noise. Reference uncertainty and other effects matter in a real calibration.
  • Independent validation data and inference diagnostics are needed before relying on the correction.
