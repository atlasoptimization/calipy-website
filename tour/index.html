LOCAL DEVELOPMENT PREVIEW

01 / Give the readings a place.

A measured value has a source, a shape, and a role in the experiment. Data Lab makes observations and their model bindings visible. This tutorial uses repeated readings of one unknown level.

02 / See the scientific relationships.

The model connects an unknown level, a known noise scale, and a measurement distribution to observed readings. Named dimensions retain the meaning of the measurement axis while the workspace displays the connections.

The workbench presents the same scientific objects owned by the Python core. A graphical view helps you discuss the model with collaborators while keeping its assumptions inspectable.

03 / Make the inference choice explicit.

Choose an inference path that matches the model and the question. The workbench exposes settings and readiness information; a successful configuration is the start of analysis, not evidence that the scientific result is valid.

The development core supports NUTS posterior inference and SVI workflows. Point estimation and posterior inference answer different questions; retain that distinction when interpreting the output.

04 / Ask what the result establishes.

For the unknown-mean problem, a small Python example compares the sampled posterior with an analytic Normal reference. For a changing sensor, the worked warm-up example compares predictions with held-out readings and a simple baseline.
