01 / Public Python package

Install CaliPy.

The package is named calipy-ppl on PyPI and is imported as calipy in Python. Use a virtual environment for your project, then install:

python -m pip install calipy-ppl

View the package on PyPI for release files and dependency requirements. Use the documentation that matches your installed release.

Check the installation before choosing an example.

Run this in the same Python environment. It prints the distribution version, import location, and whether the newer block API is present.

Verify your Python environment
python -c "import calipy; from importlib.metadata import version; print(version('calipy-ppl')); print(calipy.__file__); print('Block API:', all(hasattr(calipy, n) for n in ('block', 'LatentParameter', 'NUTS')))"

Import succeeds: continue with the documentation for that installation. Block API: False: use the earlier public interface; the development downloads below are not compatible. If import fails, check that installation and execution use the same environment and consult the package requirements.

Start in an isolated environment

On Linux or macOS:

python3 -m venv .venv
.venv/bin/python -m pip install calipy-ppl
.venv/bin/python -c "import calipy; print(calipy.__file__)"

On Windows PowerShell:

py -m venv .venv
.\.venv\Scripts\python.exe -m pip install calipy-ppl
.\.venv\Scripts\python.exe -c "import calipy; print(calipy.__file__)"
Release and preview are different. The published package is pre-alpha. The modern block API, Model Forge, and local agent bridge showcased on this site are development previews and are not all present in the public package. A matching version number alone does not establish API compatibility.

02 / Make the question explicit

Start small. Keep the assumptions visible.

  1. Identify the quantity you want to learn: a sensor offset, a stable level, or an instrument parameter.
  2. Describe how it generates observations, including the measurement noise and relevant physical effects.
  3. Follow a release-matched example, fit a small dataset, and inspect the result and diagnostics.

DEVELOPMENT PREVIEW

A complete model in the block API.

The current development interface separates the model’s scientific wiring from its observations and inference method. The example below estimates one unknown mean from repeated readings, with known measurement noise and an explicit prior.

unknown_mean.py · requires development API
import calipy as cp
import pyro.distributions as dist
import torch

reading_dim = cp.dim("reading")
data = cp.CalipyTensor(
    torch.tensor([0.8, 1.0, 1.2, 0.9]), reading_dim
)
level = cp.LatentParameter(
    "level", prior=dist.Normal(0., 2.)
)
measurement = cp.RandomVariable.Normal("reading", scale=0.15)

@cp.block
def model():
    return measurement(level())

result = model.fit(
    outputs=data,
    method=cp.NUTS(warmup_steps=100, num_samples=200, seed=23),
)
print(result[level].mean.tensor)
print(result[level].standard_deviation.tensor)

Download the complete example with an analytic reference. It needs a development checkout exposing cp.block and cp.LatentParameter; installing the public package alone may not provide them.

The downloadable example reports a posterior mean and standard deviation and compares them with the conjugate Normal reference. This is a small demonstration, not an inference-convergence guarantee.

A checked first result

In the recorded development run, the posterior mean was 0.973 and its standard deviation 0.078. The analytic reference gives 0.974 and 0.075. Small sampling differences are expected.

EXPERIMENTAL WORKBENCH

Explore Model Forge.

Model Forge is an experimental local graphical workbench over CaliPy’s core scientific model contracts. Its interface brings model construction, named dimensions, inspection, and Python interchange into one workspace.

It is not a hosted application on this website and is not bundled into the public library wheel. The current development workflow supports model inspection, inference configuration, and project persistence. Supported public distribution and broader production readiness remain in development.
